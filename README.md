# 손끝길 Android 앱

스마트폰 카메라로 키오스크 화면과 손끝을 보고, 음성과 진동으로 주문을 돕는 앱을 개발하고 있습니다.

> **현재 개발 진행 중입니다.** 아래 APK는 T08까지 구현한 테스트용 중간 버전입니다. 합성 결과 재생과 합성 좌표에 대한 실제 방향 계산을 사용할 수 있으며, 카메라 AI 인식과 실제 주문 안내는 아직 준비 중입니다.

## APK 다운로드 및 설치

**[최신 Android 테스트 APK 다운로드 · T08](https://github.com/hy2oni/sonkkeut-frontend/releases/download/v0.1.0-dev-t08/sonkkeut-0.1.0-dev-t08.apk)**

[버전 설명과 다운로드 파일 보기](https://github.com/hy2oni/sonkkeut-frontend/releases/tag/v0.1.0-dev-t08)

- APK 앱 코드 기준: `eab125eb49bb73d5abab61e9e47754eadc5dbb9c` (후속 커밋은 README 갱신)
- APK SHA-256: `9e7dded29b5d082dc1f03831d310bc48697e2e2c841fd55fcf070b0b00cb9baa`

1. Android 휴대폰에서 위 다운로드 링크를 누릅니다.
2. 다운로드한 APK 파일을 열고 설치를 진행합니다. 휴대폰이 요청하면 해당 브라우저의 ‘이 출처의 앱 설치’를 허용합니다.
3. 설치된 **손끝길**을 실행합니다.
4. 카메라 권한을 허용하면 카메라 미리보기가 표시됩니다. 마이크 권한은 별도로 허용할 수 있습니다.

- **지원 기기:** Android 8.0 이상. 현재는 Pixel_6 에뮬레이터에서 검증했으며 실물 휴대폰은 미검증입니다.
- **배포 형태:** 개발용 서명으로 만든 디버그 APK입니다. 정식 배포 버전이 아닙니다.
- Windows에서는 APK를 직접 실행할 수 없습니다. Android Studio의 에뮬레이터에 설치해 확인하세요.
- 다운로드 링크는 APK를 받는 링크입니다. 앱 설치는 Android의 설치 화면에서 사용자가 완료합니다.

## T06 개발 내용

T06에서 추가한 다음 기능은 최신 T08 APK에도 포함됩니다.

- 설치된 오프라인 한국어 음성으로 카메라 상태와 서버 연결 결과 안내
- 마지막 안내 다시 듣기, 음성·진동·카메라 함께 멈추기
- 앱을 벗어나면 출력 중지, 돌아온 뒤 사용자가 다시 시작
- 방향 안내 간격 제한과 같은 안내 반복 억제
- 실제 인식과 구분되는 방향·가까움·도달 테스트 버튼 및 유한 진동 패턴
- 한국어 음성이 없으면 화면으로 안내하고 기기 음성 출력 설정으로 이동

음성 출력은 Android TextToSpeech를 사용하며 백엔드 완성을 기다리지 않고 기기에서 처리합니다. 테스트 문장은 실제 키오스크 인식이나 주문 성공을 의미하지 않습니다. 음성 엔진과 한국어 음성 데이터가 기기에 설치되어 있어야 합니다.
네트워크 테스트 11개와 안내 정책 테스트 8개가 통과했습니다. 에뮬레이터에서 진동 실행 기록과 중지·복귀 처리를 확인했습니다. 에뮬레이터에 오프라인 한국어 음성이 없어 실제 음성 재생은 미검증입니다. 실물 기기의 소리·진동 체감과 TalkBack 사용성은 추가 확인이 필요합니다.

## T07 개발 내용: 합성 결과 재생

최신 T08 APK에는 **합성 결과 재생 · T07** 화면이 포함됩니다.

카메라 영상과 연결되지 않은 고정 안내 결과를 **다음 합성 단계** 버튼으로 재생합니다. 정상 흐름은 이동 → 가까움 → 위치 유지 → 누름 조건 → 결과 대기 → 고정 옵션 화면 결과 확인입니다. 손끝 누락 흐름은 안내를 멈추고 명시적인 재시작을 요구하며, 결제 종료 흐름은 안내를 종료합니다. 실제 화면을 누르거나 실제 결제를 진행하지 않습니다.

이전 세션·다른 keyframe·다른 target·중복 순서의 결과를 거부합니다. 앱 중지 후에는 이전 재생을 이어가지 않고 새 시나리오를 선택합니다. 자동 타이머로 성공을 판정하지 않습니다. 결과 확인도 미리 정한 fixture 값이며 실제 화면 비교가 아닙니다.

어댑터는 AI 기준 커밋 `ba55be0248c709ab9222d40c100dcb9d61362a50`의 `GuidanceDecision` 출력 의미를 참조한 앱 내부 타입입니다. AI의 Python 계산 실행이나 카메라 추론과의 동등성을 검증한 단계가 아닙니다.

## T08 개발 내용: 실제 방향 계산

AI 저장소의 `codex/visual-processing-core` 최신 커밋 `ba55be0248c709ab9222d40c100dcb9d61362a50`에서 `guidance.py`의 순수 계산을 Kotlin으로 이식했습니다. 앱의 **실제 방향 계산 · 합성 좌표 입력 · T08**에서 고정 좌표를 입력해 방향·거리·0.3초 유지·1회 누름 조건·결과 대기를 실제 계산합니다. 입력 시각은 고정된 단조 증가 시각이며 버튼을 누르는 현실 시간 간격으로 연속 유지나 성공을 판정하지 않습니다.

| 구성 | 작업 코드 상태 |
| --- | --- |
| T07 안내 및 결과 | 고정 결과 재생 |
| T08 방향·거리·유지·누름 조건 | Kotlin 실제 계산, 합성 좌표 입력 |
| 화면 모서리 변환·손끝 추적·NMS | 아직 앱에 이식하지 않음 |
| 실제 누름 결과 비교 | 미구현, T07은 고정 결과 |
| 카메라에서 좌표·버튼·문자 추출 | 미구현 |

Python 비교 자료는 `tools/generate_guidance_reference.py`로 해당 커밋의 Python 코드를 실행해 생성합니다. 다운로드한 기준 Python 소스는 Git에서 제외되는 `app/build/t08-reference`에 보관하고, 비교 입력·기대 결과는 `app/src/test/resources/guidance-reference.json`에 기록합니다. 기준 자료에는 커밋과 `guidance.py`의 SHA-256도 포함됩니다. API 타입으로 표현할 수 없는 Python의 잘못된 객체 타입은 Kotlin 입력 타입이 막으며, 유효한 관측값과 오류 경계를 비교합니다.

최신 T08 APK에는 위 계산과 검증 화면이 포함됩니다.

Python 기준 실행 결과의 8개 흐름·243개 관측과 33개 방향을 Kotlin 테스트에서 비교했습니다. 안내 종류·원인·방향·거리·유지 시간·recenter/reacquire·거리 구간 및 오류 결과를 확인했고, 수치 비교 허용 오차는 `1e-9`입니다. 이 결과는 해당 입력에 대한 비교이며 전체 AI 기능이나 실제 인식 정확도 검증이 아닙니다.

## 서버 주소가 준비되면

앱의 **서버 연결**에서 HTTPS 기본 주소를 입력하고 **주소 저장 및 연결 확인**을 누릅니다.
앱은 입력한 주소 뒤에 `/actuator/health`를 붙여 확인합니다.
주소에 로그인 정보, 쿼리 또는 `#`은 넣지 마세요.
연결·읽기 시간 제한은 각각 3초이며, 전체 요청 제한은 5초입니다.
주소 변경, 취소 또는 백그라운드 이동 시 진행 중인 요청을 취소합니다.

개발 APK에서 HTTP는 `10.0.2.2`, `localhost`, `127.0.0.1`에만 허용합니다. 제출용 빌드는 HTTPS를 사용합니다.
에뮬레이터의 `10.0.2.2`는 노트북을 가리키며, 실기기의 `localhost`는 휴대폰 자체를 가리킵니다.
에뮬레이터에 이전 테스트 주소가 남아 있다면 실제 서버 주소로 교체하세요.

## 개발자가 빌드하는 방법

Android Studio에서 이 저장소 폴더를 엽니다.
JDK 21과 Android SDK 플랫폼 36.1을 준비하고, 프로젝트 루트의 `local.properties`에 본인의 SDK 경로를 적습니다.
이 파일은 Git에 올리지 않습니다.

```properties
sdk.dir=C:/Users/USERNAME/AppData/Local/Android/Sdk
```

PowerShell에서 다음 명령으로 빌드합니다.

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug --no-daemon --console=plain
```

생성 파일: `app/build/outputs/apk/debug/app-debug.apk`
첫 실행에는 빌드 도구와 라이브러리 다운로드가 발생할 수 있습니다.

| 도구 | 버전 |
| --- | --- |
| 언어·화면 구성 | Kotlin 2.2.10, Jetpack Compose |
| 빌드 | AGP 9.0.1, Gradle Wrapper 9.1.0, JDK 21 |
| Android | 최소 API 26, compile SDK 36.1, target API 36 |
| UI | Compose BOM 2025.08.00, Activity Compose 1.10.1 |
| 카메라 | CameraX 1.6.2 |
| 생명주기 | Lifecycle Compose 2.9.2 |
| 네트워크 | OkHttp 4.12.0, Coroutines 1.10.2 |

Windows 한글 경로에서 개발하기 위해 경로 검사 우회와 JVM `file.encoding=COMPAT`를 설정했습니다.
관련 내용: [Gradle의 Windows 경로 인코딩 이슈](https://github.com/gradle/gradle/issues/30391).

## 로컬 테스트 서버

실제 백엔드 대신 연결 처리를 확인하는 간단한 서버입니다. Python 3으로 실행합니다.

```powershell
python tools/health_fixture.py
```

에뮬레이터의 서버 기본 주소에 `http://10.0.2.2:18885/up`을 입력합니다.
`/up`은 정상, `/down`은 준비 실패, `/invalid`는 잘못된 응답, `/timeout`은 지연 응답을 반환합니다.
서버는 노트북의 `127.0.0.1`에만 열리며 `Ctrl+C`로 종료합니다.
