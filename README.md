## T07 개발 내용: 합성 결과 재생

최신 APK에는 **합성 결과 재생 · T07** 화면이 포함됩니다.

카메라 영상과 연결되지 않은 고정 안내 결과를 **다음 합성 단계** 버튼으로 재생합니다. 정상 흐름은 이동 → 가까움 → 위치 유지 → 누름 조건 → 결과 대기 → 고정 옵션 화면 결과 확인입니다. 손끝 누락 흐름은 안내를 멈추고 명시적인 재시작을 요구하며, 결제 종료 흐름은 안내를 종료합니다. 실제 화면을 누르거나 실제 결제를 진행하지 않습니다.

이전 세션·다른 keyframe·다른 target·중복 순서의 결과를 거부합니다. 앱 중지 후에는 이전 재생을 이어가지 않고 새 시나리오를 선택합니다. 자동 타이머로 성공을 판정하지 않습니다. 결과 확인도 미리 정한 fixture 값이며 실제 화면 비교가 아닙니다.

어댑터는 AI 기준 커밋 `ba55be0248c709ab9222d40c100dcb9d61362a50`의 `GuidanceDecision` 출력 의미를 참조한 앱 내부 타입입니다. AI의 Python 계산 실행이나 카메라 추론과의 동등성을 검증한 단계가 아닙니다.

API 타입으로 표현할 수 없는 Python의 잘못된 객체 타입은 Kotlin 입력 타입이 막으며, 유효한 관측값과 오류 경계를 비교합니다.

최신 APK에는 위 계산과 검증 화면이 포함됩니다.

Python 기준 실행 결과의 8개 흐름·243개 관측과 33개 방향을 Kotlin 테스트에서 비교했습니다. 안내 종류·원인·방향·거리·유지 시간·recenter/reacquire·거리 구간 및 오류 결과를 확인했고, 수치 비교 허용 오차는 `1e-9`입니다. 이 결과는 해당 입력에 대한 비교이며 전체 AI 기능이나 실제 인식 정확도 검증이 아닙니다.

### B 작업: 앱 흐름 통합

**통합 계산·복구 · B**에서 합성 카메라 모서리·버튼 검출·21개 손 관절을 좌표 변환 → NMS/ID → 손끝 평균 → 방향/누름 조건 → 기대 화면·정확한 항목 수량 비교로 연결합니다. 단순 결과 재생과 구분되며 카메라 추론·OCR·주문 해석·결제 실행은 없습니다.

정상 전환, 정확한 수량, 손끝 누락, 화면 누락, 목표 화면 변경, 예상 밖 결과, 결과 시간 초과, 결제 종료 시나리오를 단계별로 실행합니다. 복구·종료 후 자동 재누름은 없으며 새 시나리오를 명시적으로 선택합니다. 앱 중지·복귀 시 기존 세션을 폐기하고 이전 세션·중복 결과를 거부합니다. 누름 전 keyframe 변경은 목표를 무효화하고, 누름 뒤에는 새 화면을 기대 결과와 비교합니다.

`ObservationAdapter`는 향후 실제 모델 연결 경계입니다. `SessionObservation`은 세션/순서/keyframe, 같은 단조 시계의 촬영·처리 시각, 픽셀 모서리·관절, 정규화 검출, 화면 종류와 선택적 정확한 항목 수량을 받습니다. `SessionTarget`의 목표 ID와 기대 효과는 외부 주문 계획기가 제공합니다. 현재 구현체는 `SyntheticObservationAdapter`뿐입니다. 실제 모델 호출과 출력 변환은 아직 미구현이며, 연결 시 회전·크롭·좌표계 및 항목 키 규칙을 합의해야 합니다.

합성 시각은 고정값입니다. 버튼을 누르는 실제 시간 간격으로 유지시간이나 주문 성공을 판단하지 않습니다. 실제 어댑터는 계산 호출을 직렬화하고 추론을 UI 스레드 밖에서 실행해야 합니다. 현재 고정 입력의 수동 단계 실행은 UI에서 수행하며 영상 큐나 모델 런타임은 추가하지 않았습니다.

누름 안내 전에는 0.2초보다 오래 처리된 좌표를 거부합니다. 결과 화면은 A의 촬영 시각·1.5초 판정 규칙을 적용해 늦게 처리된 유효 증거와 늦게 촬영된 화면을 구분합니다. 통합 모드에서는 기존 단독 테스트와 서버 자동 음성이 세션 안내를 덮지 않도록 처리했습니다.

A·B 통합은 최신 APK에 포함됩니다.

통합 세션 테스트 6개와 중지 후 오래된 안내 제거 테스트를 포함해 총 46개 테스트가 통과했습니다. 에뮬레이터에서 전체 계산의 1회 누름 조건과 새 옵션 화면 결과 확인, 앱 복귀 후 세션 중지·다음 관측 비활성화를 확인했습니다. 나머지 복구·수량·결제 종료 시나리오는 자동 테스트로 검증했으며 실제 모델·한국어 음성·실기기 검증은 남아 있습니다.

### C 작업: 사용성 점검·중간 배포

총 46개 테스트, 디버그 APK 빌드, Pixel_6 설치·실행 및 버전 확인을 완료했습니다. 오프라인 한국어 음성이 없어 화면 안내로 대체되는 상태를 확인했습니다. TalkBack이 활성화되면 앱 자동 TTS를 억제하고 명시적인 다시 듣기를 유지하도록 보완했습니다.

에뮬레이터에서 TalkBack 서비스 연결·touch exploration 활성화와 앱의 한국어 접근성 노드, 일반 키보드의 일시 정지 버튼 포커스를 확인했습니다. TalkBack 알림 권한 안내가 나타나 실제 읽기·포커스 순서·조작 점검은 완료하지 못했습니다. 권한은 허용하지 않았고 접근성 설정은 원래 비활성 상태로 복원했습니다. 실제 한국어 음성 재생·TalkBack 사용성·실물 휴대폰 검증은 미검증입니다.

최신 개발 APK는 포크 릴리스에 게시합니다. 개발 브랜치는 develop이며, 이번 배포는 원본 PR·병합이나 main 병합을 포함하지 않습니다.

## 서버 주소가 준비되면

앱의 **서버 연결**에서 HTTPS 기본 주소를 입력하고 **주소 저장 및 연결 확인**을 누릅니다.
앱은 입력한 주소 뒤에 `/actuator/health`를 붙여 확인합니다.
주소에 로그인 정보, 쿼리 또는 `#`은 넣지 마세요.
연결·읽기 시간 제한은 각각 3초이며, 전체 요청 제한은 5초입니다.
주소 변경, 취소 또는 백그라운드 이동 시 진행 중인 요청을 취소합니다.

개발 APK에서 HTTP는 `10.0.2.2`, `localhost`, `127.0.0.1`에만 허용합니다. 제출용 빌드는 HTTPS를 사용합니다.
에뮬레이터의 `10.0.2.2`는 노트북을 가리키며, 실기기의 `localhost`는 휴대폰 자체를 가리킵니다.
에뮬레이터에 이전 테스트 주소가 남아 있다면 실제 서버 주소로 교체하세요.

## 개발자가 빌드하는 방법

Android Studio에서 이 저장소 폴더를 엽니다.
JDK 21과 Android SDK 플랫폼 36.1을 준비하고, 프로젝트 루트의 `local.properties`에 본인의 SDK 경로를 적습니다.
이 파일은 Git에 올리지 않습니다.

```properties
sdk.dir=C:/Users/USERNAME/AppData/Local/Android/Sdk
```

PowerShell에서 다음 명령으로 빌드합니다.

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug --no-daemon --console=plain
```

생성 파일: `app/build/outputs/apk/debug/app-debug.apk`
첫 실행에는 빌드 도구와 라이브러리 다운로드가 발생할 수 있습니다.

| 도구 | 버전 |
| --- | --- |
| 언어·화면 구성 | Kotlin 2.2.10, Jetpack Compose |
| 빌드 | AGP 9.0.1, Gradle Wrapper 9.1.0, JDK 21 |
| Android | 최소 API 26, compile SDK 36.1, target API 36 |
| UI | Compose BOM 2025.08.00, Activity Compose 1.10.1 |
| 카메라 | CameraX 1.6.2 |
| 생명주기 | Lifecycle Compose 2.9.2 |
| 네트워크 | OkHttp 4.12.0, Coroutines 1.10.2 |

Windows 한글 경로에서 개발하기 위해 경로 검사 우회와 JVM `file.encoding=COMPAT`를 설정했습니다.
관련 내용: [Gradle의 Windows 경로 인코딩 이슈](https://github.com/gradle/gradle/issues/30391).

## 로컬 테스트 서버

실제 백엔드 대신 연결 처리를 확인하는 간단한 서버입니다. Python 3으로 실행합니다.

```powershell
python tools/health_fixture.py
```

에뮬레이터의 서버 기본 주소에 `http://10.0.2.2:18885/up`을 입력합니다.
`/up`은 정상, `/down`은 준비 실패, `/invalid`는 잘못된 응답, `/timeout`은 지연 응답을 반환합니다.
서버는 노트북의 `127.0.0.1`에만 열리며 `Ctrl+C`로 종료합니다.
