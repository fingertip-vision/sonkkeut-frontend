# 손끝길 · Kotlin Android 앱 0.2.3

**현재 개발 진행 중입니다.** 시각장애인·저시력 사용자가 키오스크 화면을 카메라로 비추고, 주문할 메뉴를 말하거나 입력하면 화면 인식과 손끝 이동 안내로 주문을 돕는 앱입니다. 결제는 키오스크에서 직접 진행합니다. 실제 키오스크에서 혼자 주문을 끝낼 수 있는지는 아직 현장 검증이 필요합니다.

## 이번 AI 연결 변경 · 0.2.3

- 매장 메뉴의 **관련 표현·분류·설명**을 후보 추천에 활용하도록 연결했습니다. 관련 표현을 정확한 주문 별칭으로 바꾸거나 자동 주문하지 않습니다.
- 매장별 캐시·SQLite 처리 후에도 현재 메뉴의 관련 표현·설명·가격을 보존합니다.
- 직접 주문·음성 보정에서 정식 메뉴 이름을 다른 메뉴의 별칭보다 우선합니다. 품절 정식 메뉴를 다른 별칭 상품으로 자동 대체하지 않습니다.
- **현재 기본 서버는 관련 표현·설명을 아직 제공하지 않습니다.** 실제 등록 데이터가 있어야 새 검색 효과를 사용할 수 있습니다. 기존 메뉴 데이터는 그대로 동작합니다.

AI 모델 가중치 개선이나 LLM·재료/알레르기 추론은 이번 변경에 포함하지 않습니다.

## 현재 주문 화면 · 0.2.2 UX 유지

| 항목 | 현재 동작 |
|---|---|
| 주문 후 안내 | 인식 원문·보정 결과 창과 ‘안내 시작’ 버튼을 없앴습니다. 정상 주문이면 주문 확인 내용을 보여주면서 바로 안내합니다. |
| 음성 인식 | 자체 Whisper만 사용합니다. 기기 음성 인식과 음성 모델 선택 화면을 제거했습니다. 한국어 음성 안내에는 Android TTS를 계속 사용합니다. |
| 주문 확인 화면 | 카메라를 줄이고 스크롤 없이 표시합니다. 긴 주문은 글자 크기를 유지하면서 이전·다음 페이지로 확인합니다. |
| 설정·종료 | 메인 상단에 ‘설정 → 노란색 종료’를 표시합니다. 첫 시작 화면에는 종료가 없습니다. 설정에는 화면·카메라·음성 항목만 제공합니다. |
| 음성 재인식 | 안내 계속·중지 대신 버튼을 배치했습니다. **기능은 미구현이며 버튼도 비활성**입니다. 재안내는 유지합니다. |
| 설정·앱 복귀 | 안내 중 설정에서 돌아오면 새 화면을 확인해 재개합니다. 다른 앱으로 갔다가 돌아오면 중지 상태이며 ‘카메라 다시 시작’을 누릅니다. |

메뉴가 불확실하거나 품절·미등록·수량·옵션 오류가 있으면 바로 안내하지 않습니다. 추천 후보를 고른 경우에도 수량·옵션을 다시 입력해야 합니다. 화면 인식과 누름 결과 확인, 매장별 메뉴 보정·캐시, 서버 자동 연결은 유지합니다. AI 가중치 5개는 0.2.1과 같습니다.

## 사용 순서

1. 앱을 열고 준비가 끝나면 **손끝길 시작**을 누릅니다.
2. 카메라로 키오스크의 전체 화면을 비춥니다. 화면과 메뉴가 준비되면 주문 입력을 요청합니다.
3. 자체 음성 모델을 준비한 뒤 말하거나 **직접 입력 주문**을 사용합니다. 예: ‘따뜻한 아메리카노 두 잔하고 카페라떼 한 잔 포장해 주세요.’
4. 정상적으로 해석되면 주문 확인 내용을 표시하면서 안내를 시작합니다. 오류나 후보 선택 요청이 있으면 내용을 수정합니다.
5. 음성·화면 안내를 따라 손끝을 움직이고 키오스크 버튼을 직접 누릅니다. 앱은 화면 변화와 담기 결과를 확인합니다.
6. 안내를 끝내려면 상단의 노란색 **종료**를 누릅니다. 결제는 키오스크에서 직접 진행합니다.

현재 환경 설정에는 서버·매장 변경과 화면 전체/상세 글자 읽기 진입점이 없습니다. 해당 내부 연결·추론 코드는 남아 있지만 사용자가 이 화면에서 실행할 수는 없습니다. 기본 서버와 매장 메뉴에 자동 연결하며, 주소가 바뀌면 앱의 기본 연결 설정을 갱신해야 합니다.

- Kotlin 단위 테스트 **83개 통과** (새 AI 연결 검사 9개 포함).
- Android 15 전체 검사: **19개 통과·카메라 프레임 대기 1개 시간 초과·음성 추론 1개 생략**. 카메라 검사는 단독 재실행에서 통과했습니다. 생략한 항목은 실제 Whisper 모델/음성 입력 파일을 사용하는 추론 검사입니다.

- APK 빌드·서명·업데이트 설치·실행과 카메라 미리보기, 큰 글자 주문 페이지 표시를 확인했습니다. 서버 상태·매장 메뉴·모델 목록 연결 및 영상/OCR·메뉴 DB 검사도 통과했습니다.

## 개발 환경과 브랜치

현재 개발 기준 브랜치는 **develop_ux**입니다. `develop_ai`에서 완료한 AI 연결·검증·APK 0.2.3 배포 결과를 사용자 승인에 따라 `develop_ux`에 반영했습니다. 포크와 원본 저장소의 `develop_ux`를 같은 코드 기준으로 유지합니다. APK 빌드 소스는 `d6efa0f`이며, AI 기준 커밋은 `d9938b2f3e999b093942c4a882264a3fbc2ca8b8`입니다.

**Kotlin + Jetpack Compose + CameraX**를 사용합니다. Android Studio에서 저장소의 **루트 폴더**를 여세요. 루트 `app/`가 현재 Android 앱이며 `android/`와 기존 TypeScript 파일은 이전 구현 참고 자료입니다.

두 저장소를 같은 부모 폴더에 둡니다.

```text
workspace/
  sonkkeut-frontend/  ← Android Studio에서 Open
  sonkkeut-ai/
```

AI 저장소는 `codex/unified-ai-20261003` 브랜치에서 위 커밋을 체크아웃합니다. JDK 17, Android SDK 35와 AI 모듈 빌드에 필요한 NDK·CMake를 준비하고 `JAVA_HOME`·`ANDROID_HOME` 또는 Android Studio의 SDK 경로를 지정하세요.

```powershell
.\gradlew.bat :app:assembleRelease :app:testDebugUnitTest
# 에뮬레이터 또는 기기를 연결한 뒤
.\gradlew.bat :app:connectedDebugAndroidTest
```

빌드 결과는 `app/build/outputs/apk/release/app-release.apk`입니다. APK 설치만 할 때는 개발 도구와 AI 소스 저장소가 필요하지 않습니다. [Android Studio 실행·모듈 설명](docs/native-kotlin.md)을 참고하세요.

[이전 버전의 개발·배포 기록](docs/readme-history-through-0.2.1.md)은 당시 사용법과 검사 결과를 보존한 문서입니다. 현재 앱 사용법은 이 README를 기준으로 확인하세요.
