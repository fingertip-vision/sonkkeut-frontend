## 재현이 필요한 현상

사용자는 키오스크 화면을 계속 인식하는 상태에서 주문하면 확인 창이 보이지 않고 바로 메뉴 탐색이 진행된다고 보고했다. 현재 submit()은 주문 설정 직후 beginOrderGuidance()를 호출하며, 별도의 확인 창 표시 완료 단계는 없다. UI는 order/paused/detailMode/textOrderOpen/recording/speechBusy 조합으로 표시를 결정한다. 그러나 S4 메뉴 안내 상태 자체가 확인 창을 숨기는 조건은 아니므로 빠른 인식만을 확정 원인으로 단정할 수 없다.

재현 조건은 화면을 먼저 찾은 뒤 음성/직접 입력, 주문 해석 중 새 프레임 도착, 후보 선택 뒤 재입력, 설정·백그라운드 복귀다. 성공 주문별 독립적인 확인 창 표시 상태를 두고 화면 인식 상태 변경이 그 표시를 취소하지 않도록 한다. 품절·모호한 후보·잘못된 주문은 성공 확인 창과 자동 안내 대상으로 만들지 않는다.

권장 흐름은 정상 주문 해석 → 확인 팝업 표시 → 주문 내용 안내 → 자동 메뉴 탐색이다. 안내 시작 버튼을 다시 만들지 않는다. 자동 닫힘 대신 닫기·주문 보기 동작을 제공하는 안을 검토하고, 주문 읽기와 방향 안내 음성의 겹침을 방지한다. 주문 내용 페이지 상태는 담기 진행 갱신 때문에 매번 첫 페이지로 돌아가지 않도록 분리한다.

## 별도 QA

순차 Android 검사에서 초기 카메라 프레임 대기가 45초를 넘긴 현상은 0.2.2/0.2.3 양쪽에 재현된다. 단독 검사는 통과했으며 원인은 미확정이다. 레이아웃 축소와 같은 원인이라고 단정하지 않고 카메라 바인딩·해제·화면 생명주기·분석 큐의 재현 로그를 별도로 점검한다.

## 제안 작업 순서

1. 성공 주문/입력/후보/모델 준비/오류/현재 안내의 UI 표시 상태와 짧은 문구 정책 정리.
2. 하단 안내를 단일 영역으로 통합하고 입력 UI를 상태별로 단순화.
3. 카메라를 유지하는 주문 확인 팝업과 한 페이지/여러 페이지 탐색 적용.
4. 빠른 프레임 갱신 중에도 성공 주문 확인 표시를 보장하고 자동 안내/음성 순서를 검증.
5. 잘못된 회복 안내를 실제 동작으로 연결하고 카메라 검사 시간 초과를 별도로 조사.
6. 작은 화면·큰 글자·음성/직접 입력·후보·권한·설정/앱 복귀 검증 후 APK 제작.

현재 정책: 자체 Whisper만 사용, 음성 재인식은 미구현 비활성 버튼, 시작 화면은 종료 없음, 안내 화면은 설정→노란색 종료, 음성 인식 원문/보정 결과 창 및 안내 시작 버튼 없음. 이 정책은 개선 작업에서도 유지한다.
