# Kotlin 0.2.3 — 매장별 검색 정보와 주문 확인

## 매장별 로컬 검색 DB

메뉴·설정 → **이 매장 메뉴 검색 정보**에서 실제 매장 메뉴를 고르고 관련 표현과 설명을 저장한다. 예를 들어 까르보나라에 `크림 파스타`를 관련 표현으로 등록할 수 있다. 이는 같은 음식이라는 확정 별칭이 아니라 사용자 확인이 필요한 검색 후보다.

- SQLite에 서버 주소·매장 코드·메뉴명 단위로 저장한다. 다른 매장에는 적용하지 않는다.
- 관련 표현 30개(각 80자), 설명 500자까지 저장하고 삭제할 수 있다.
- 서버가 `search_terms` 배열과 `description`을 제공하면 이를 읽고 오프라인 메뉴 캐시에도 유지한다. 해당 필드가 없어도 기존 서버와 호환된다.
- 정식 이름·별칭은 기존 정확 검색으로 찾고, 관련 표현·분류·설명은 확인이 필요한 후보 검색에 사용한다.
- 현재 매장에 실제로 등록된 메뉴만 반환한다. 품절·가격 정보를 검색 메모가 덮어쓰지 않는다.
- 등록 정보는 검색용이다. 재료·알레르기·영양성분에 관한 검증된 사실로 사용하지 않는다.

현재 구현은 온디바이스 검색 DB와 검색 규칙이다. 범용 음식 데이터셋, 학습된 신경망 임베딩, LLM은 추가하지 않았다. 매장 관련 정보는 기존 서버 데이터와 사용자가 등록한 검색 메모에서 가져온다.

## 장바구니 항목 대조

OCR이 `커피 2개 6,000원`처럼 메뉴명과 수량을 한 줄에서 확실하게 읽으면 주문 목록의 해당 메뉴 수량과 대조한다. 다른 수량이면 결제 안내를 보류한다. 총 수량·금액이 같아도 읽힌 항목이 다르면 그대로 진행하지 않는다. 장바구니 글자가 바뀌면 이전 결제 안내 동의를 다시 받는다.

메뉴명과 숫자가 별도 영역에 있거나, 중복 OCR 행이 있거나, 옵션까지 대조할 수 없으면 상세 검증이 불완전함을 알린다. 화면에서 읽지 못한 항목을 없다고 판단하지 않는다. 기존 수량·합계 검사와 결제 전 확인도 유지한다.

실제 키오스크에 담긴 상품의 수정·삭제는 아직 자동 연결하지 않는다. 상품 행과 조작 버튼의 대응 관계 및 변경 결과를 검증할 수 있는 매장별 화면 예시가 필요하다.

## 결제 완료 문구와 주문 번호 읽기

음성 주문 안내가 결제 화면에 도달하면 완료 화면 읽기로 이어진다. 메뉴·설정의 **결제 완료·주문 번호 읽기**에서도 시작할 수 있다. 카메라 권한과 AI 준비가 필요하며 마이크는 사용하지 않는다.

- 사용자가 직접 결제를 마친 뒤 키오스크 완료 화면을 비춘다.
- 완료 문구를 명확히 읽고 두 개의 새 분석 화면에서 같은 내용을 확인한다.
- `주문 번호: 0012` 같은 번호는 앞자리 0을 보존해 읽는다. 경쟁하는 여러 번호가 있으면 하나를 추측하지 않는다.
- `수령장소: …`, `픽업장소: …`가 명시되면 해당 문구를 함께 읽는다.
- `결제 완료 후 …` 같은 설명문이나 결제 실패·취소 문구를 완료로 해석하지 않는다.
- 읽기를 마치면 카메라 안내를 중지한다. 2분 동안 확인하지 못하면 미확인으로 종료한다.
- 음성은 **화면에서 읽힌 문구**라고 설명한다. 결제 서버의 승인 확인이나 결제 실행 기능은 아니다.

실물 S26 Ultra, 실제 매장의 여러 화면 배치, 마이크 및 TalkBack 사용성은 별도로 검증해야 한다. 자동 테스트와 에뮬레이터 검증 기록은 `knowledge-checkout-validation.json`을 참고한다.

단위 테스트 107개, Android 에뮬레이터 테스트 23개가 통과했다. 신규 검증은 관련 표현·설명 검색, 품절 배제, 장바구니 읽기 불확실성, 완료 문구·번호의 새 프레임 일치, SQLite의 서버·매장별 격리와 재시작 후 보존, 검색 정보 편집 화면 및 완료 읽기 모드 종료를 포함한다. 실제 매장의 결제 화면 사진이나 실제 사용자 음성으로 성능을 평가한 결과는 아니다.
