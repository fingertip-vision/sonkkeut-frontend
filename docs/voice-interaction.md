# 화면별 음성 주문과 탐색 · Kotlin 0.2.1

현재 로컬 앱 0.2.2에서는 아래 수량 확인 뒤에 여러 메뉴의 주문 목록 편집·전체 확인 단계를 추가했다. [0.2.2 변경과 사용법](order-improvements.md)을 우선 참고한다. 이 문서의 단일 메뉴 예시와 검증 수는 0.2.1 기록이다.

메뉴·설정에서 **음성만으로 단계별 주문**을 누른 뒤 카메라·마이크 권한을 허용한다. 설치된 자체 Whisper v3를 우선 사용하며, 자체 모델이 없으면 기기에 제공되는 온디바이스 음성 인식을 사용한다. 둘 다 준비되지 않았으면 모델 준비 화면으로 이동한다. 오프라인 한국어 TTS도 필요하다. 앱의 대화 입력·영상은 외부 LLM 서버로 보내지 않는다.

## 실제 대화

첫 화면을 먼저 읽는다. 매장/포장 화면이면 이용 방법, 분류 버튼만 있는 화면이면 현재 보이는 분류를 먼저 묻고 안내한다. 자체 Whisper가 설치돼 있으면 메모리에 준비한 뒤 질문을 시작해 첫 발화를 준비 시간에 놓치지 않게 한다. 아래는 메뉴 화면부터 시작한 예다.

1. 앱: “메뉴 이름만 말씀해 주세요.” → 사용자: “아메리카노.”
2. 낮거나 제공되지 않은 음성 점수: “아메리카노 맞으신가요?” → “네”, “아니요” 또는 즉시 다른 메뉴 이름으로 수정한다.
3. “몇 개 드릴까요?” → “두 개.” 수량을 확인한 뒤 메뉴 버튼을 찾는다.
4. 매장/포장 화면에서만 이용 방법을 묻는다. 옵션 화면에서 온도와 크기를 각각 한 질문씩 묻는다. 화면에 없는 옵션은 받아들이지 않는다.
5. 장바구니 수량·금액을 검사하고 결제 화면으로 안내해도 되는지 음성으로 확인한다. 결제 화면에서 안내를 마친다.

확인·수정 단계에는 앱 버튼을 누를 필요가 없다. “아니요”는 재입력, 다른 선택을 바로 말하면 이전 후보 교체, “재안내”는 질문 반복, “취소/안내 중지”는 종료다. 인식 실패 3회 뒤에는 현재 선택 예시와 “다시/취소”를 안내한다. 실제 키오스크 터치와 스크롤은 사용자가 수행하며 앱은 손끝 위치·동작을 안내하고 새 화면으로 결과를 확인한다.

## 모듈과 상태

| 모듈 | 역할 |
|---|---|
| `VoiceDialogManager` | `PROMPTING → LISTENING → VERIFYING/RETRY_VOICE_CAPTURE → WAITING_SCREEN`, 음성 수정·취소·재안내, 화면 문맥에 한정된 선택 |
| `NativeConversation` | 화면 상태와 대화 결합, 단계별 주문, TTS 완료 후 STT 시작, 비동기 결과의 세대 번호 검사 |
| `ScreenNavigator` | 확실하게 읽힌 메뉴·유효한 좌표만 선택, 스크롤 → 탭/다음 페이지, 방문 탭·추정 스크롤 단계·화면 글자 지문·시간 제한 |
| `MenuMatcher` | 로컬 SQLite 메뉴 스냅샷의 이름·별칭 정확 검색, 편집 거리, 등록된 음식 개념 벡터의 코사인 추천 |
| `VisionVerifier` / `DetailScanner` | 사용자 요청 뒤 근접 촬영, 겹치는 2×3 타일의 ML Kit 줄 검출과 기존 M3 OCR, 결과 구분·시간 초과·취소 |

화면 종류가 바뀌거나 옵션 버튼 문맥·장바구니 금액이 바뀌면 이전 음성 확인을 무효화한다. 옵션 값은 현재 주문의 해당 항목에만 반영하고 수량·이미 담은 진행은 보존한다. 카메라 중지, 메뉴 페이지 이동, 앱 배경 전환, 매장/메뉴 변경 시 음성 세션을 종료한다. 이전 TTS 완료·STT·영상 결과가 다음 화면의 동작을 시작할 수 없다.

## 확인 기준

기기 STT의 유효한 confidence가 0.90 이상, 또는 Whisper의 유효한 sequence score가 -0.15 이상이고 no-speech가 0.20 미만이면 현재 화면의 정확한 선택에 대해 “선택할게요”를 말한 뒤 진행할 수 있다. 점수가 없거나 낮으면 반드시 “맞으신가요?”를 묻는다. 점수는 공급자별 **휴리스틱**이며 정확도 확률로 보정된 값이 아니다. 실제 녹음으로 기준을 검증해야 한다. Whisper sequence score와 기기 confidence를 같은 숫자로 비교하지 않는다.

미등록 메뉴·모호한 별칭·유사/의미 추천은 음성 점수가 높아도 임의로 확정하지 않는다. 추천 수락, 주문 변경, 결제 화면 진입은 명시적 음성 응답을 요구한다. TTS가 성공적으로 끝난 뒤에만 마이크를 열어 안내 음성을 다시 주문으로 듣는 일을 막는다. TTS 실패·오디오 포커스 상실 시 대화를 중지한다.

## 탐색과 복구

확실한 메뉴가 없으면 메뉴 영역에서 아래→위 스크롤을 안내한다. 손끝 위치·펴진 검지·신뢰도를 확인하고 움직임을 읽지만, 손가락 이동만으로 스크롤 성공으로 판단하지 않는다. 새 OCR 메뉴 지문이 필요하다. 탭별 스크롤 최대 3단계, 탭 최대 4개, 전체 액션 최대 12개, 전체 탐색 90초로 제한한다. 같은 화면이 유지되면 대기·다른 탭으로 전환한다. 명시적인 스크롤 메타데이터가 없는 외부 키오스크이므로 오프셋은 물리적 픽셀이 아닌 탐색 단계다.

찾지 못하면 먼저 비슷한 실제 매장 메뉴를 제안한다. “아니요, 꼭 있어야 해요” 또는 정밀 검색 수락 뒤에만 근접 모드로 전환한다. 가까이 비추고 “읽어줘”라고 하면 촬영한다. 읽은 뒤 “다음 구역/다시 읽기/취소”로 진행한다. 카메라는 근접 시 1920×1440을 우선 요청하고 미지원 기기는 대체 해상도를 선택한다. 분석은 원본을 최대 긴 변 2400으로 제한하고 겹치는 6개 타일을 읽는다. 작업당 약 8초의 협력적 처리 예산, 3구역·세션 90초의 상한을 둔다. 진행 중인 단일 네이티브 추론은 반환될 때까지 즉시 중단되지 않을 수 있으나 취소된 결과는 버린다.

근접 읽기로 목표를 확인하면 전체 화면으로 돌아와 **새 화면에서 버튼 좌표를 재확인**한다. 부분 촬영 좌표는 키오스크 목표 좌표로 쓰지 않는다. 읽지 못했거나 제한 내에 못 찾았다는 이유로 메뉴가 실제로 없다고 단정하지 않는다. 매장 DB 미등록, 영상 읽기 실패, 읽은 구역에서 미관찰, 근접 읽기로 확인, 시간 초과, 취소를 구분한다. 전체 키오스크 메뉴를 모두 순회했다는 외부 증거가 없으므로 실제 메뉴 부재를 확정하는 기능은 포함하지 않는다.

## 검증 범위

단위 테스트 83개, Android 에뮬레이터 18개를 검사한다. 새 검사에는 음성 확인/수정·화면 전환·재스캔/취소의 스크립트 재현 5개와 실제 ML Kit/M3 타일 OCR 1개가 포함된다. 스크립트 재현은 입력 텍스트와 TTS 완료 이벤트를 주입한 검사이며 실물 마이크 대화가 아니다. 기존 Whisper JNI 합성 PCM·모델·메뉴 DB·CameraX 검사도 유지한다.

현재 의미 추천은 소규모 음식 개념 사전의 코사인 벡터이며 사전 학습된 신경망 임베딩이나 LLM이 아니다. 예를 들어 매장에 까르보나라가 등록돼 있으면 “크림 파스타”의 관련 후보로 제안할 수 있지만 동일한 음식·레시피라고 확정하지 않는다. 음식 관계의 범위를 늘리려면 매장별 별칭·메타데이터와 검증 데이터가 더 필요하다. 모델 재학습은 수행하지 않았다. S26 Ultra 실제 음성·키오스크·스크롤 동작·TalkBack 검증은 아직 필요하다.

구현 참고: Android [TTS 완료 콜백](https://developer.android.com/reference/android/speech/tts/UtteranceProgressListener)과 [ML Kit Android OCR](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)의 실행·이미지 수명 규약을 따른다.
