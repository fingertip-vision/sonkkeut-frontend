# Kotlin 0.2.2 — 주문 목록과 추가 옵션

## 사용 순서

1. 메뉴·설정에서 **음성만으로 단계별 주문**을 시작한다.
2. 메뉴와 수량을 말하고 확인하면 **주문 목록 확인** 화면이 열린다. 아직 키오스크 조작을 시작하지 않는다.
3. `메뉴 추가`로 다음 메뉴를 말한다. 최대 10항목, 항목당 1~10개를 준비할 수 있다.
4. `첫 번째 하나 더`, `2번 두 개로 변경`, `두 번째 삭제`, `되돌리기`로 수정한다. 수정은 확인 응답 뒤 반영한다. 같은 메뉴가 여러 항목이면 번호로 구분한다.
5. `주문 시작`을 말하면 전체 목록을 다시 읽고 동의를 받는다. 이후 목록 순서대로 실제 키오스크 버튼 안내를 시작한다.

주문 목록 화면에서도 항목별 수량 증감·삭제·되돌리기·확인 버튼을 사용할 수 있다. 카메라 메인 화면은 기존처럼 스크롤 없이 유지한다. 앱 목록 편집은 키오스크에 이미 담긴 상품을 수정하거나 취소하지 않는다. 안내 시작 후 편집은 제공하지 않는다.

## 화면에서 읽은 추가 옵션

온도·크기에 이어 화면의 확실한 버튼에서 다음 선택을 묻는다.

- 당도: 0/25/30/50/70/75/100%
- 얼음: 없음/적게/보통/많이
- 샷: 추가 없음/기본 샷/1~3샷 추가

번호나 화면의 선택지 이름으로 답하고 확인한다. 화면에 없는 옵션, 불확실한 글자, 중복 버튼 이름, 유효하지 않은 좌표는 선택지로 만들지 않는다. 옵션 버튼을 누른 뒤 새 화면의 선택 결과를 확인하는 기존 흐름을 사용한다. 토핑·세트·매장 고유 옵션을 모두 이해하는 범용 기능은 아니다.

추가금액이 버튼에 표시되면 수량에 맞춰 예상 합계에 반영한다. 추가금액이 없으면 무료라고 가정하지 않는다. 예상 합계를 계산할 수 없다는 점과 실제 장바구니에서 읽은 합계를 결제 안내 전에 알린다. 장바구니 수량·합계를 읽지 못하거나 예상값과 다르면 결제 안내를 보류한다. 메뉴별·옵션별 장바구니 상세 대조는 아직 별도 구현이 필요하다.

## 검색·접근성·복구

- 검색 후보를 최대 3개 읽어주고 이름이나 번호로 선택하게 한다. 유사 메뉴 선택에는 명시적 확인이 필요하다.
- 메뉴의 정식 이름이 다른 상품의 별칭과 충돌하면 정식 이름을 우선한다. 품절된 정식 메뉴를 다른 별칭 상품으로 자동 대체하지 않는다.
- 메뉴마다 화면 탐색 제한 시간을 새로 시작한다.
- 화면 검색 실패 시 진행 중인 주문을 지우지 않는다. 재촬영을 거절하면 주문을 유지한 채 안내를 중지하고 키오스크 장바구니 확인을 요청한다.
- 접근성 설정에 **음성 선택을 항상 다시 확인**을 추가했다. 기본은 켜짐이다. 꺼도 주문 수정·유사 후보·추가 옵션·결제 안내는 확인한다.

## 남은 범위

실제 키오스크에 담긴 항목의 음성 삭제·수정, 임의의 토핑·세트 구성, 실제 결제 및 영수증·수령 안내, 매장 자동 식별, 범용 음식 지식 DB/LLM, 정식 서버 주소·배포 서명은 이번 변경에 포함하지 않는다. S26 Ultra의 실제 마이크·카메라, 소음 환경, 시각장애인 사용자의 TalkBack 사용성은 실물 검증이 필요하다.

단위 테스트와 Android 재현 테스트의 결과는 `order-improvements-validation.json`에 기록한다. 음성 대화 재현은 인식 텍스트와 TTS 완료 이벤트를 주입하며 실제 마이크 발화 성능을 측정하는 검사가 아니다.
