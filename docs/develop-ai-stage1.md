# develop_ai · AI 연결 1단계 기준 확인·동기화

2026-10-06. 사용자 승인 범위는 기준 확인과 AI 모듈 동기화까지다.

## 기준과 변경

- 프론트 작업 브랜치: `develop_ai`.
- 생성 기준: `develop_ux`의 `e8ada931a4ddec5a295ba64672be5773dfef957b`.
- 작업 시작 시 프론트와 AI 저장소 모두 미커밋 변경사항 없음.
- AI 브랜치: `codex/unified-ai-20261003`.
- 기존 AI 커밋: `80d3dfcdaec24144334e1236319237bf44651154`.
- 최신 확인·반영 커밋: `d9938b2f3e999b093942c4a882264a3fbc2ca8b8` (2026-10-06 01:33:44 KST).
- AI 저장소만 fast-forward로 동기화했다. 프론트의 다른 브랜치와 병합하지 않았다.
- 루트 `settings.gradle.kts`가 형제 저장소 `../sonkkeut-ai/android/sonkkeut-native`를 직접 포함한다. 이후 APK 빌드에서 이 최신 모듈을 사용한다. 기존 배포·설치 APK는 그대로다.

AI 변경은 세 파일(모듈 README, MenuMatcher.kt, MenuSpeechIndex.kt)이다. `MenuDocument`에 기본값이 있는 `relatedTerms`·`description`을 추가했으며 기존 호출 인자는 유지된다. 메뉴 추천은 등록 관련 표현·분류·설명을 후보 근거 `store_knowledge`로 사용한다. `MenuMatcher.exact`는 정식 이름을 다른 메뉴의 별칭보다 우선하고 품절 정식 메뉴를 다른 별칭 상품으로 자동 대체하지 않는다. 모델 가중치·Whisper JNI 변경은 없다.

## 다음 단계에서 연결·검증할 부분

현재 프론트는 관련 표현·설명을 서버 메뉴 파싱과 추천용 메뉴 객체에 전달하지 않는다. 정식 이름 우선 규칙 역시 별도로 구현된 프론트 주문 파서에 자동 반영되지 않는다. 2단계에서 실제 제공 데이터 범위를 확인하고 연결하며, 데이터가 없는 기존 메뉴의 호환성과 후보 선택·품절 차단 정책을 유지한다. 아직 앱 동작 검증을 수행하지 않았으므로 이번 동기화를 기능 연결 완료로 해석하면 안 된다.

## 보류한 프론트 QA

1. 주문 확인 시 카메라가 과도하게 축소됨.
2. 짧은 주문에도 주문 확인 영역이 남은 공간의 85~92%를 점유함.
3. 이전·다음은 주문 내용 페이지 이동인데 한 페이지에서도 비활성 버튼을 보여 주문 진행 버튼으로 혼동됨.
4. 화면 인식 오류 문구가 이미 제거한 화면 읽기 진입점을 사용하라고 안내함.

카메라 크기를 유지하고 주문 확인을 팝업으로 분리하는 방안은 검토 후보이며 확정·구현하지 않았다. QA 수정은 사용자가 모아서 진행하기로 했으므로 이번 AI 연결 작업에서 변경하지 않는다.

## 단계 종료 상태

프론트 실행 코드·버전·README 수정, 테스트 실행, APK 빌드·설치, 커밋·푸시·배포를 수행하지 않았다. AI 적용·검증 작업이 성공적으로 끝나면 사용자 지시에 따라 `develop_ai` 결과를 `develop_ux`에 병합하는 전략이다. 현재는 병합하지 않았다.
