## 구현과 실제 데이터

서버가 제공하는 관련 표현(related_terms 또는 relatedTerms)·설명을 MenuDocument에 전달한다. 기존 이름·별칭·품절·분류·가격과 원문 오프라인 캐시를 유지한다. 매장별 SQLite가 생략하는 선택적 정보는 현재 카탈로그의 같은 정식 이름으로 복원한다. 다른 매장의 메뉴 이름으로 복원하지 않는다.

직접 주문 파서·음성 보정 입력·메뉴 적용에서 정식 이름과 충돌하는 다른 메뉴의 별칭을 제외한다. 품절 정식 이름도 예약하고 일반 중복 별칭은 모호성 처리를 유지한다. 관련 표현·설명은 추천 정보이며 확정 주문 별칭으로 승격하지 않는다. 추천 후보 선택 후 수량·옵션을 다시 입력하는 기존 흐름을 유지한다.

확인한 기본 서버 `/api/stores/Z9XZSN/menu`는 HTTP 200, 메뉴 버전 1, 메뉴 3개였다. 관련 표현·설명은 제공하지 않는다. 따라서 실제 등록 정보의 새 검색 효과는 미검증이며 입력 자료가 준비되면 활용하는 연결 상태다. 임의 데이터를 실제 매장에 추가하지 않았다.

- 시간 초과한 카메라 검사만 다시 실행하면 **1개 통과**. 전체 한 번의 실행이 모두 통과했다고 보고하지 않는다.
- 릴리스 APK 자체 순차 검사 4개: 주문 자동 안내·설정 복귀·종료 등 **3개 통과**, 카메라 초기 프레임 대기는 시간 초과.
- 이전 **0.2.2 APK에 동일 네 검사 순서를 적용해도 3개 통과·같은 카메라 시간 초과 1개**를 재현했다. 신규 AI 연결에만 나타나는 현상은 아니며 원인은 미확정이다.
- 최신 릴리스 APK의 카메라 검사 단독 재실행 **1개 통과**. 순차 검사 안정성 문제는 기존 QA에 추가해 보류한다.
- 릴리스 APK 빌드·필수 lint·서명 검증 성공. 기존 0.2.2 위 업데이트 설치 성공, 설치 버전 0.2.3/code13 확인.

빌드/검사 명령은 `:app:testDebugUnitTest :app:assembleRelease :app:connectedDebugAndroidTest`다. 첫 전체 실행은 위 카메라 검사로 실패했으며, 후속 `:app:assembleRelease` 및 지정 카메라 검사 실행에서 BUILD SUCCESSFUL을 확인했다. 전달 APK 검사는 AndroidJUnitRunner를 릴리스 앱에 직접 실행했다.

## QA 및 병합

카메라 축소, 짧은 주문 창의 큰 빈 공간, 이전·다음 버튼 용도 혼동, 제거된 화면 읽기를 권하는 오류 안내는 그대로다. 주문 확인 팝업은 검토안이다. 위 순차 카메라 검사 시간 초과도 추가 기록했다. 이 AI 작업에서는 QA 레이아웃·카메라 코드를 수정하지 않았다.

사용자가 승인한 저장소 반영 범위는 포크 `develop_ai` 커밋·푸시·개발 APK 배포·README 다운로드 링크 최신화다. 원본 PR #6은 여전히 포크 `develop_ux` → 원본 `develop_ux`이며 이번 브랜치를 자동 반영하지 않는다. 병합 직전 전략을 다시 보고하고 사용자의 명시적 승인을 받는다.
