# 매장 등록 없는 현장 메뉴 — Kotlin 0.2.5

앱의 기본 메뉴 출처를 **현장 화면 인식**으로 변경했다. 시연 매장 DB에 있는 상품이 임의의 다른 매장에 있다고 가정하지 않는다. 미등록 매장에서 메뉴 다운로드·매장 코드를 요구하지 않으며, 카메라에서 관찰한 메뉴로 주문을 시작한다.

## 동작

1. 사용자는 시작 후 키오스크 메뉴 화면 전체를 비춘다. 읽기 가능한 검출 메뉴 영역에서 서로 다른 두 화면 프레임으로 이름을 확인한다. 버튼·가격·장바구니 행·옵션은 메뉴 사전에 임의로 추가하지 않는다.
2. 관찰한 이름으로 이번 방문의 임시 카탈로그를 구성한다. 확실하게 읽은 가격만 보관하고 가격이 충돌하거나 읽히지 않으면 가격 미확인으로 둔다. 품절 표시가 읽히면 후보에서 제외한다.
3. 음성 주문은 등록된 매장 목록 없이 시작할 수 있다. 화면에서 읽은 메뉴와 번호를 안내하고 수량·옵션·주문 목록을 확인한다. ‘다른 메뉴 보기’로 스크롤/탭 이동을 안내한다. 아직 못 본 메뉴 이름을 말하면 다른 페이지와 탭을 탐색해 확인한다.
4. 이동한 메뉴 화면에서 추가로 확인한 상품을 방문 목록에 모은다. 최종 주문을 확정하면 목록을 고정하고, 실제 화면의 상품과 위치를 계속 대조한다. 미리 넣은 공통 음식 이름을 실제 판매 상품으로 취급하지 않는다.
5. 기존 카페 옵션과 명시적 맵기·굽기 옵션을 읽는다. 분류하지 못한 옵션은 화면에 있는 글자/번호 그대로 질문한다. 사용자 확인 후 그 버튼으로 안내하며, ‘선택 완료’를 확인하기 전 자동 담기 안내를 보류한다. 직접 입력 주문은 화면 읽기 페이지에서 옵션을 선택하고 완료를 누를 수 있다.
6. 장바구니 수량·금액, 결제 후 완료 문구·주문 번호는 기존 검증/읽기 흐름으로 연결한다. 실제 결제는 사용자가 수행한다. 화면을 읽지 못하면 결제 성공이나 메뉴 부재를 단정하지 않는다.
7. 다음 매장에서는 메뉴·설정의 ‘새 키오스크 시작’을 누른다. 이전 주문/관찰 목록/메뉴 ID/위치 확인을 지우고 새 방문으로 시작한다. 앱 재실행 시 관찰 목록은 복원하지 않는다. 방문 메뉴는 서버에 업로드하지 않는다.

## 등록 DB와 공통 지식의 역할

백엔드 메뉴는 등록 매장을 명시적으로 선택했을 때 사용하는 보조 경로다. 서버·매장 설정에서 현장 모드를 끄면 기존 메뉴 API와 오프라인 캐시를 사용한다. 현장 모드에서는 시연 매장 메뉴 요청을 보내지 않으며 통계도 이전 매장 코드로 전송하지 않는다.

‘크림 파스타’ 같은 표현을 실제 화면의 ‘까르보나라’와 연결하는 데는 기존 음식 개념 후보 추천을 쓸 수 있다. 다만 유사성만으로 상품이나 좌표를 확정하지 않고 사용자 확인과 현재 화면 검증을 거친다. 향후 일반 음식 지식 DB/RAG를 확장하더라도 실제 판매 메뉴 목록과 분리해야 한다.

AI 서버는 이 기본 흐름의 필수 구성 요소가 아니다. 추후 복잡한 문장·대규모 음식 지식 검색을 서버로 보완할 수 있으나 결과는 현재 관찰 메뉴의 ID 후보로 제한한다. 메뉴가 보이지 않는 상황을 LLM으로 추측해 해결하지 않는다.

## 현재 범위와 한계

**매장 등록이 불필요한 구조이며 모든 매장의 전체 기능을 보장한 상태는 아니다.** 한국어 OCR과 현행 화면/요소 검출 모델이 읽을 수 있는 화면에서 동작한다. 가림·반사·작은 글자·새로운 화면 구성·해외 언어·그림만 있는 메뉴·읽기 불확실한 요소는 재읽기나 수동 확인이 필요하다. 탭/스크롤은 사용자가 수행하며 현재 검출 영역을 이용해 안내한다.

옵션의 의미와 그룹을 자동으로 완전히 이해하지 않는다. 미분류 옵션은 사용자가 읽힌 선택을 확인하며, 실제 필요한 선택을 마쳤다는 확인을 받는다. 실제 키오스크의 필수 선택/금액 변경/누름 성공 검증을 대신하지 않는다. 이름이 같은 상품의 가격이 다르면 가격을 추측하지 않고, 중복 위치도 기존 공통 매칭기로 선택을 보류한다.

이번 변경은 메뉴 출처와 주문 흐름의 개선이다. OCR/손끝/음성 가중치 재학습이나 범용 LLM 도입은 없다. 실제 여러 업체 키오스크, 실물 휴대폰 카메라/마이크의 성공률 검증이 추가로 필요하다.
